# 「行行出状元」通用能力层 · 正式路由服务 (cli)

> 架构·经理 | 2026-09-05 | 由 poc(R4/R5/R6) 验证脚本升级为正式可维护服务

## 背景
poc/ 下 R4(单直连) / R5(复合≥2岗) / R6(多单元索引) 已验证路由技术栈
(bash/awk + YAML 声明式, 无重前端)。本 `cli/` 把三者**收敛为一个正式入口**，
从「验证脚本」升级为「可维护路由服务」, 并落实用户**仓库收敛策略**。

## 仓库收敛策略(用户口径)
- **非重点/非大型行业尽量集中本仓开发**, 不轻易开多仓、不过度跨仓。
- 确属**大行业/重点行业**才后续拆独立仓迁移；**不阻碍本仓开发推进**。
- `units.yaml` 中 `repo_ref` 拆仓前留空/待回填，集中本仓开发期只增能力描述，
  不依赖源仓存在。

## 使用
```bash
cli/route cli/units.yaml "<一句话意图>"
```
- 输入：`units.yaml`(路由索引) + 用户意图文本
- 输出：行业(单元) + 岗位(角色) 路由判定

## 路由能力(整合 R4/R5/R6)
| 场景 | 行为 | 对应POC/里程碑 |
|------|------|----------------|
| 单意图单岗位 | 单直连 -> unit@role | R4 / CP2 |
| 单意图 ≥2 岗(同行业) | 复合装配 M6 并装, 前缀零突变 | R5 / CP3 |
| 命中唯一行业单元 | 路由到该单元 | R6 / CP2 |
| 命中多行业单元(跨界) | 提示拆子任务走 M5 交接 | R6→CP3 交接 |
| 行业+岗位均未命中 | 回落 L2 人工一次确认 | 人工两头化 |

## 设计约束(延续架构 v0.2)
- **一会话一行业一稳定前缀**: 同 session 禁止跨行业, 岗位前缀取固定并集零突变。
- **人工两头化**: 仅入口(行业/意图确认)与出口(交付复核)人工, 中间 0 人工。
- **岗位词过滤**: 岗位命中必须落在该单元 `roles` 声明内才路由(防越权路由)。

## 文件
- `route`  — 正式入口可执行
- `units.yaml` — 路由索引(每单元: id/ref/industry/alias/tags/roles)
- 行业接入规范: `docs/industry/register-spec.md`
