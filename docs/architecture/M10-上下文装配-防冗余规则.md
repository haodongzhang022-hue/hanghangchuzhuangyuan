> 前置设计：架构·总师（Issue #11 决策文档）

---

## 0. 问题定义

Issue #11 原始诉求：「防止每次提交带全部秘书提示词」。核心痛点：

1. **Token 冗余**：静态角色定义+全量上下文+全量任务原文每次都全量上送 API；
2. **上下文污染**：无关岗位/历史任务被塞进每次调用；
3. **缓存命中破坏**：若动态上下文与稳定前缀混排进 cache-key 区间，改一次全量失效。

## 1. 分层模型（M10 核心）

```
┌────────────────────────────────────────────────────────┐
│ 一份"会话上下文"不再是一整坨文本，而是三层物理隔离结构    │
└────────────────────────────────────────────────────────┘

┌ 层A【静态·缓存键】系统提示词骨架 ──────────────────────┐
│  角色定义 + 岗位前缀 + 行为/输出契约                    │
│  ⇒ 缓存命中键只看这一层                                 │
│  ⇒ 一次性装配，session 内恒定，禁止运行期改写           │
└────────────────────────────────────────────────────────┘
        ↑ 稳定，永不混入动态
┌ 层B【会话态】StateCard 展开要素 ───────────────────────┐
│  目标 + 当前执行任务要素 + 目录/文件/工具/依赖           │
│  ⇒ compact_context() 生成，折叠任务只给编号引用         │
└────────────────────────────────────────────────────────┘
        ↑ 一个 session 一份，按需刷新
┌ 层C【注入·按规则】局部触发上下文 ──────────────────────┐
│  本地规则命中才拼装的"本次动作相关片段"                 │
│  例：读到的某文件 diff / 某条交接卡/检索到的索引          │
│  ⇒ 独立注入，与 A 层完全隔离                            │
└────────────────────────────────────────────────────────┘
```

## 2. 防冗余规则（六条）

| 编号 | 规则 | 实现模块 |
|------|------|---------|
| R1 | 角色/前缀静态注册，不随行上送 | M3 PrefixArchive + M10-a 层A |
| R2 | 一人一对话（session 边界即信息边界） | M4 会话编排 + M5 交接卡 |
| R3 | **本地规则触发，不靠每次全量上下文** | **M10-b RuleEngine** |
| R4 | 原文落盘 + 引用，不全量携带 | M9 FoldEngine.content_ref |
| R5 | 动态注入与静态层隔离（缓存保护核心） | **M10-d CacheGuard** |
| R6 | 增量而非全量 | M9 compact_context() |

> R3 + R5 是 M10 的核心新增；R1/R2/R4/R6 由 M1-M9 已有机制覆盖。

## 4. R3 规则表设计（M10-b）

**核心思想**：把"何时需要哪些信息"写成声明式触发规则表，按规则命中才去本地拉取/装配对应片段。

### 4.1 数据结构

```yaml
ContextRule:
  rule_id: str              # 规则唯一编号
  name: str                 # 规则名称
  triggers: [str]           # 触发关键词/正则列表
  target_layer: A|B|C       # 目标层
  data_source: str          # 数据来源标识
  enabled: bool             # 是否启用
  priority: int             # 匹配优先级
  match_mode: keyword|regex # 匹配模式
```

### 4.2 默认规则集（内置兜底）

| 规则ID | 名称 | 数据源 | 触发场景 |
|--------|------|--------|---------|
| R3-FILE-01 | 文件/代码操作 | file.diff | 修改/编辑/代码/文件 |
| R3-STAT-01 | 状态管理 | state.card | 状态/进度/任务/StateCard |
| R3-HAND-01 | 交接/接力 | handoff.card | 交接/接力/跨单元 |
| R3-ARCH-01 | 架构/设计 | architecture.docs | 架构/设计/方案 |
| R3-TEST-01 | 测试 | test.code | 测试/回归/验证 |
| R3-DATA-01 | 数据/配置 | data.files | 注册/规则/yaml |

### 4.3 规则表承载

- 声明式 YAML：`data/context-rules.yaml`
- 数据驱动扩展：改规则不改代码
- 程序内置默认规则作为兜底

## 5. M10-a 装配器 API

```python
from hanghang.context import ContextAssembler, RuleEngine, CacheGuard

assembler = ContextAssembler(
    rule_engine=RuleEngine(),                    # M10-b 规则引擎
    source_providers={                            # 数据源注入器
        "file.diff": lambda ctx: "...",
        "test.code": lambda ctx: "...",
    },
)

result = assembler.assemble(
    session_id="sess-1",
    role_name="secretary",
    unit_id="dongjiagoushi",
    user_text="帮我修改代码并补充测试",
    static_prefix="[秘书]",
)

# result: {
#   layer_a: 静态层(缓存键域),
#   layer_b: 会话态层,
#   layer_c: 规则注入层,
#   full_context: 完整分层拼装,
#   hit_rules: [...],
#   cache_key: 仅层A的哈希,
#   layer_sizes: {A: n, B: n, C: n},
# }

# 缓存保护
guard = CacheGuard()
check = guard.validate_isolation(result["layer_a"], session_id="sess-1")
```

## 6. 与 M1-M9 的关系

| M10 依赖 | 已有机制 | 复用方式 |
|---------|---------|---------|
| 层A 静态前缀 | M3 PrefixArchive | 读取 prefix-archive.json |
| 层B 会话态 | M9 FoldEngine.compact_context | 直接调用 |
| 层C 注入片段 | M5 HandoffCard / M8 Registry | 通过 provider 回调装配 |
| 缓存隔离 | M3 前缀稳定约束 | CacheGuard 强化校验 |

## 7. 关键设计决策

1. **缓存键只看层A**：层A哈希作为 cache_key，任何动态上下文变化不影响缓存命中。
2. **动态上下文走独立注入通道**：层B/C 物理隔离，不混入层A。
3. **规则表声明式**：`data/context-rules.yaml` 数据驱动，改规则不改代码。
4. **静默失败**：provider 异常不影响整体装配（try/except 包裹）。
