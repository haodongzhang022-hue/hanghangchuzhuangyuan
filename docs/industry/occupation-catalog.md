# 职业分类大典参考表（1636 个职业 + 编码）

> 解决的问题：职业库只有 178 条，是"能被行业单元承接"的收敛基线，不是职业全集。
> 想补一个职业时，靠记忆现编名字——造词、重名、粒度乱跳，改一次行业名就漏一批。
> 这里接上国家标准：**《职业分类大典（2022 年版）》的 1636 个细类职业，每个都有编码。**

## 编码长什么样

大典细类编码是四段：`大类-中类-小类-细类`。

```
4-14-02-02  健康管理师
│ │  │  └─ 细类（职业，1636 个）
│ │  └──── 小类（449 个）
│ └─────── 中类（79 个）
└───────── 大类（8 个）
```

八大类：1 负责人 / 2 专业技术人员 / 3 办事人员 / 4 社会生产生活服务人员 /
5 农林牧渔 / 6 生产制造 / 7 军队人员 / 8 不便分类。

> 你记的 `000392` 那种写法是招聘网站自己的**岗位库内码**，各家一套、互不通用、
> 也不公开。国家层面唯一的公共编码就是上面这套四段码，另外大典中类/小类还带
> `GBM` 码（如 `GBM41402`），本仓库都收进去了。

## 两个文件，两种身份

| 文件 | 身份 | 能否改 |
|------|------|--------|
| `data/reference/occupation-catalog-2022.yaml` | 大典原样收下：8/79/449/1636，含职业描述、L(绿色)/S(数字) 标记 | **只读**，来自社会公示稿 |
| `data/reference/occupation-gb-map.yaml` | 我们职业 ↔ 大典 code 的人工映射（70 条 / 67 个 code） | 随职业增补手工维护 |

为什么不全量倒进 `industry-occupations.yaml`：

大典 1636 条里绝大多数既没有付费方也没有可交付物。军队人员、采矿工种、
不便分类的其他从业人员……塞进职业库只会把覆盖率稀释成没意义的数字。
**它们在补全缺口时才是财富** —— 所以单独放参考表，按需查表挑，而不是
伪装成"已登记职业"。

## 两个分母，各管一件事

| 指标 | 当前值 | 含义 |
|------|--------|------|
| 映射率 | 111/178 = **62.4%** | 我们的职业名有多少挂上了国家标准锚点 |
| 大典覆盖度 | 101/1636 = **6.2%** | 标准里的细类还剩多少可选 |

**6.2% 不是"还差 93.8% 没做完"。** 大典覆盖天然很低——它包住了整个国民经济，
而我们只做能被数字员工/服务提供者承接的那部分。这个数字的用处是
"还剩多少可以挑"，不是"还欠多少账"。

映射率才是进度指标，测试里有 40% 下限守着。

## 映射原则：宁缺勿错

只登记口径对得上的。我们的职业名很多比大典细类更细（"品牌策划"、"新媒体运营"、
"关卡设计师"、"民宿运营"）或更粗，大典里没有对应细类 —— 这类**一律留空**。

错挂比不挂坏得更彻底：`gb_code` 一挂上，反查类目、导出、覆盖统计全都跟着错。

- `exact`：与大典细类同名（律师、导游、美发师、心理咨询师…）
- `near`：语义等价的近义名（"测试工程师" → 计算机软件测试员）

多个我们的职业可以指向同一个 code（翻译 / 口译员 / 字幕翻译 都归「翻译」），
反向统计按 code 去重，不虚增。

## 国际那一层：ISCO-08

大典是本国口径，跨境对齐、海外招聘、国际统计比对都接不上。ISCO-08（ILO）
是各国职业分类的公共母版，已落 `data/reference/occupation-catalog-isco08.yaml`：

```bash
python3 src/hanghang/cli/main.py reference isco --search nurse
python3 src/hanghang/cli/main.py reference isco --code 2512
```

两套标准**各自独立**，不做"一套覆盖另一套"的假设（口径不同，硬套必然错挂）。
四根轴的分工与接法见 `docs/industry/global-framework.md`。

## 怎么用

```bash
# 按关键词找大典里有什么（补职业时先查表，别现编）
python3 src/hanghang/cli/main.py industry catalog --search 护士

# 按编码查归属链路 + 谁挂了这个职业
python3 src/hanghang/cli/main.py industry catalog --code 4-14-02-02

# 还没被我们挂上的大典细类（候选池，不是待办）
python3 src/hanghang/cli/main.py industry catalog --gaps --major 2 --limit 30

# 覆盖快照（映射率 + 分类分布 + S/L 覆盖）
python3 src/hanghang/cli/main.py industry catalog

# 职业列表现在带大典编码列
python3 src/hanghang/cli/main.py industry occupations --partition healthcare
```

导出后 `GB_CATALOG` / `gb_catalog` 表随 `industry-db.json`、`occupations.csv`、
`industry.sqlite` 一起走。拿到制品库就能直接查，不必再去找原始 PDF。

## 自检守住什么

`industry check` 里有第 14 条校验专管参考表：

1. `stats` 自述的规模与实际条数一致（手工改数据后 stats 不能变成谎话）
2. 细类 code 唯一，且 major/middle/minor 父级都真实存在
3. 映射的 `gb_code` 必须真实存在于目录
4. 映射的 `occur_id` 必须真实存在于职业库 —— **职业改名后映射会悬空，
   `gb_code_of` 静默返回空串，这种失效比没有映射更坏**
5. 一个 `occur_id` 只能挂一条（重复会让查询静默取首条）
6. 参考表整体缺失时单独报一条，不假装"没有映射所以没问题"

`tests/test_occupation_catalog.py` 共 18 项，另守两条暗沟：
加了大典后 `occupation_coverage` 分母**不许变**（仍是 baseline 165，不被 1636 稀释）；
映射率有 40% 下限，挡住"映射全删还自称通过"。

## 边界

- 数据源是社会公示稿，非人社部正式发布版。字段口径以正式版为准，
  编码体系（四段码）两者一致。
- 大典里"数字职业 S"(97) / "绿色职业 L"(133) 标记来自职业名尾注，
  不是独立字段；本仓库已把它拆成 `marks` 数组。
- 未接招聘网站的私有岗位库内码（各平台不通用、不公开）。
  TAPD/招聘侧若要对接，按各自 API 单独做适配层，别把内码当国家标准。
