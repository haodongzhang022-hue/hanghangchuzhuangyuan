# 数据分析 · Agent 使用说明

> 本说明面向需要对接/调用本行业能力的上层 **AI Agent**（路由 / 编排 / 下游执行 Agent）。
> 通过通用能力层知识库检索可注入 Agent 提示词。数据同步自 `data/unit-index.yaml`（unit_id=`data-analytics`）。

## 一、行业定位

- **unit_id**：`data-analytics`
- **行业标签**：数据分析
- **行业别名**：数据分析、数据挖掘、大数据、商业分析、数据报表、经营分析、数据洞察、分析报告、数据报告
- **入口地址**：_集中本仓，repo_ref 待回填_

> 本行业面向 **数据分析** 相关诉求。上层路由 Agent 依据行业别名与关键词自动识别并路由至此行业。

## 二、能力范围

- 数据分析
- 报表设计
- 商业洞察
- 数据可视化
- 经营分析
- 预测分析

## 三、可路由岗位

| 岗位 | 前缀 | 职责 | 典型触发词（示例） |
|------|------|------|-------------------|
| data_analyst | [数分] | 数据分析 数据报表 商业分析 数据可视化 | 数据分析、数据报表、商业分析、数据可视化、经营分析、报表分析 |
| data_scientist | [数科] | 数据挖掘 机器学习建模 特征工程 预测模型 | 数据挖掘、机器学习建模、特征工程、预测模型、算法建模、预测分析 |
| bi_engineer | [BI] | 数据仓库 ETL BI报表 数据管道 | 数据仓库、ETL、BI报表、数据管道、看板报表、数据报告 |

> 岗位说明：单会话内绑定本行业后，可按需路由到上述任一岗位；同一行业的多岗位可复合装配。

## 四、路由接入方式

将用户诉求文本送入通用能力层路由（`route`），由 M1 按 **行业 → 岗位** 两级识别自动路由至本行业。

```bash
python3 src/hanghang/cli/main.py route "<诉求文本>"
# 指定会话（SLIB：首次路由自动绑定本行业）
python3 src/hanghang/cli/main.py route "<诉求文本>" --session "<session_id>"
```

## 五、使用约束

- **会话级行业绑定（SLIB）**：一个 session 绑定一个行业，会话内不得静默跨行业；跨行业诉求触发交接（需新会话）。
- **稳定前缀**：本行业岗位前缀为 `[数分], [数科], [BI]`，会话内稳定不变。
- **跨行业交接**：经 M5 交接总线建 HandoffCard 接力，不做同会话拼接。
