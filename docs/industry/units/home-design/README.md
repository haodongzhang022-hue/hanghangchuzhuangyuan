# 家装设计 · Agent 使用说明

> 本说明面向需要对接/调用本行业能力的上层 **AI Agent**（路由 / 编排 / 下游执行 Agent）。
> 通过通用能力层知识库检索可注入 Agent 提示词。数据同步自 `data/unit-index.yaml`（unit_id=`home-design`）。

## 一、行业定位

- **unit_id**：`home-design`
- **行业标签**：家装设计
- **行业别名**：装修、家装、室内设计、装饰、家居设计、装潢、全屋定制、软装、硬装、房屋装修、新房装修、老房翻新、局部改造
- **入口地址**：_集中本仓，repo_ref 待回填_

> 本行业面向 **家装设计** 相关诉求。上层路由 Agent 依据行业别名与关键词自动识别并路由至此行业。

## 二、能力范围

- 装修方案

- 施工管理
- 全屋定制

| 岗位 | 前缀 | 职责 | 典型触发词（示例） |
|------|------|------|-------------------|
| interior_designer | [室内设计] | 室内设计 户型方案 装修设计 效果图 | 室内设计、室内装修设计、户型设计、空间设计、装修设计、家装设计 |

| project_manager | [装修经理] | 施工管理 装修监理 装修预算 | 装修施工、施工管理、装修监理、装修预算、装修报价、预算报价 |

> 岗位说明：单会话内绑定本行业后，可按需路由到上述任一岗位；同一行业的多岗位可复合装配。

## 四、路由接入方式

将用户诉求文本送入通用能力层路由（`route`），由 M1 按 **行业 → 岗位** 两级识别自动路由至本行业。

```bash
python3 src/hanghang/cli/main.py route "<诉求文本>"
# 指定会话（SLIB：首次路由自动绑定本行业）
python3 src/hanghang/cli/main.py route "<诉求文本>" --session "<session_id>"
```

## 五、使用约束

- **会话级行业绑定（SLIB）**：一个 session 绑定一个行业，会话内不得静默跨行业；跨行业诉求触发交接（需新会话）。
- **稳定前缀**：本行业岗位前缀为 `[室内设计], [软装], [装修经理]`，会话内稳定不变。
- **跨行业交接**：经 M5 交接总线建 HandoffCard 接力，不做同会话拼接。
