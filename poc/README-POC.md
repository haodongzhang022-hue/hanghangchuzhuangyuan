## 结论(回填「待开发确认」)
1. **路由命中**: 岗位词→角色→单元映射最小可行；岗位词典需按单元演进维护。
2. **岗位优先于行业别名判定** 可消除歧义(评审 vs 架构冲突)。
3. **置信兜底**: 无命中回落到 L2 入口人工一次确认，符合人工两头化。
4. **复合缺口(M4/M6)**: 当前 M1 仅单岗位路由。复合意图需多槽位二次扫描 + M4 编排判定 —— 属 R5 开发项，本 POC 明确暴露。
5. **行业归属**: 单单元POC 无法充分验证多单元路由；待 R3 在源仓落地 + 扩展第二单元后做多单元命中回归。

## 技术栈结论(供拍板)
- 「bash/awk 轻量脚本 + YAML 解析」满足 M1/M2 最小 POC，**无需重前端/重运行时代理**。
- 复合/交接/跨界(M4/M5/M6) 复杂装配需在此基础上叠加编排抽象，本 POC 验证其可行性边界。
- 结论回填 ARCHITECTURE.md 决策表「技术栈」格 = **轻量脚本编排式 v0 已验证**，待 R3/R5 扩展。
